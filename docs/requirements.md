# Elasticsearch Index管理アプリケーション 要件定義書

## 1. プロジェクト概要

### 1.1 目的
Elasticsearchのインデックス操作を効率的に行うためのデスクトップアプリケーションを提供する。データの抽出・分析作業を支援し、ローカル環境でのデータ管理を容易にする。

### 1.2 背景
- Elasticsearchのデータを定期的に抽出・分析する必要がある
- GUIとCLIの両方のインターフェースを提供し、様々な利用シーンに対応
- 抽出したデータをローカルDBに保存し、オフライン分析を可能にする

### 1.3 対象ユーザー
- データエンジニア
- システム管理者
- データアナリスト
- Elasticsearchを利用する開発者

## 2. 技術スタック

| カテゴリ | 技術 | 備考 |
|---------|------|------|
| フロントエンド | React + TypeScript | UIコンポーネント開発 |
| デスクトップフレームワーク | Tauri | Rustベースの軽量なデスクトップアプリ |
| バックエンド | Rust | Tauriのバックエンド処理 |
| ローカルDB | DuckDB | 分析用OLAP データベース |
| 接続先 | Elasticsearch | データソース |

## 3. 機能要件

### 3.1 Elasticsearch接続管理
- **接続設定**
  - ホストURL（例: https://localhost:9200）
  - ユーザー名
  - パスワード/APIキー
  - 接続プロファイルの保存・読み込み機能
- **接続テスト**
  - 設定した接続情報の疎通確認
  - クラスタ情報の取得・表示

### 3.2 サンプルインデックス作成
- **インデックス作成機能**
  - インデックス名の指定
  - マッピング設定（基本的なフィールド型定義）
  - サンプルデータの投入（テスト用JSON）
- **テンプレート機能**
  - 一般的なインデックスパターンのテンプレート提供
  - カスタムテンプレートの保存

### 3.3 データ抽出・検索
- **検索条件指定**
  - クエリDSL（JSON形式）
  - シンプルな検索（フィールド指定、値指定）
  - 時間範囲指定
  - 検索結果のプレビュー
- **抽出オプション**
  - 取得件数の指定
  - ページネーション
  - 特定フィールドのみ抽出

### 3.4 ローカルデータベース保存
- **DuckDBへの保存**
  - 抽出データのテーブル化
  - テーブル名の指定
  - データ型の自動推定
  - 追記モード/上書きモード選択
- **保存データの管理**
  - 保存済みテーブル一覧表示
  - テーブルのプレビュー
  - テーブルの削除

### 3.5 ユーザーインターフェース

#### 3.5.1 GUI（Tauri）
- **ダッシュボード画面**
  - 接続状態の表示
  - 最近使用したプロファイル
- **接続設定画面**
  - 接続情報の入力フォーム
  - プロファイル管理
- **インデックス管理画面**
  - インデックス一覧
  - インデックス作成フォーム
- **データ抽出画面**
  - 検索条件入力
  - 結果プレビュー
  - DuckDB保存実行
- **ローカルDB管理画面**
  - 保存済みテーブル一覧
  - SQLクエリ実行（簡易）

#### 3.5.2 CLI
- **基本コマンド**
  ```bash
  # 接続設定
  es-client connect --host <url> --user <username> --password <password>

  # インデックス作成
  es-client create-index --name <index-name> --template <template-name>

  # データ抽出
  es-client extract --index <index-name> --query <query.json> --output <table-name>

  # ローカルDB操作
  es-client db list
  es-client db query --table <table-name> --sql <query>
  ```

## 4. 非機能要件

### 4.1 セキュリティ
- 認証情報の暗号化保存
- パスワードの平文表示防止
- HTTPS通信のサポート
- SSL証明書検証オプション

### 4.2 パフォーマンス
- 大量データ取得時のメモリ効率化（ストリーミング処理）
- 検索結果のページネーション対応
- DuckDBへの効率的なバルク挿入

### 4.3 運用性
- 設定ファイルのエクスポート/インポート
- エラーログの記録
- 実行履歴の保存
- クロスプラットフォーム対応（Windows, macOS, Linux）

### 4.4 ユーザビリティ
- 直感的なGUI操作
- エラーメッセージの分かりやすさ
- 操作のアンドゥ機能（可能な範囲で）

## 5. 制約事項

### 5.1 技術的制約
- Elasticsearchのバージョン: 7.x以降を想定
- DuckDBファイルサイズ: 利用可能なディスク容量に依存
- 同時接続: 単一のElasticsearchクラスタへの接続

### 5.2 機能的制約
- 複雑なアグリゲーションクエリは対応範囲外（シンプルな検索に特化）
- リアルタイムストリーミングは非対応
- インデックスの編集・削除機能は初期バージョンでは未実装

## 6. 今後の拡張性

### 6.1 将来的な機能追加候補
- 複数Elasticsearchクラスタの同時管理
- データ可視化機能（グラフ、チャート）
- スケジュール実行機能（定期的なデータ抽出）
- クエリのテンプレート化
- エクスポート機能（CSV, JSON, Parquet）
- インデックスのバックアップ/リストア

## 7. 成功基準

- Elasticsearchへの接続が安定して行える
- サンプルインデックスが正しく作成できる
- 指定した条件でデータが正確に抽出できる
- 抽出したデータがDuckDBに正しく保存される
- GUIとCLIの両方で主要機能が利用可能
- クロスプラットフォームで動作する
